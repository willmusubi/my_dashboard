# 安全性与可维护性审查

适用于高风险计画、合并（merge）前，以及一般的代码变更 code review。

## 审查优先顺序

1. 功能性错误与回归问题。
2. 安全性错误。
3. 隐私外泄。
4. 身分验证与权限瑕疵。
5. 数据验证缺口。
6. 迁移（migration）与回滚（rollback）风险。
7. 架构偏移。
8. 重复代码与可维护性。
9. 缺失的测试或薄弱的验证。

## 必要输出

```text
发现的问题：
- 严重程度：
- 文件/行号（若可取得）：
- 问题：
- 影响：
- 建议修法：

残留风险：
批准建议：批准 | 要求修改 | 阻挡
```

## 可维护性检查项目

- 遵循既有模式。
- UI 变更取用 `ai/context/design-system.md` 的 token 与组件，没有硬写的一次性色彩／间距／字级；新做的组件已登记回组件库 inventory。
- 避免重复抽象。
- 除非规格要求，否则保持公开 API 稳定。
- 保持函数与组件聚焦、单一职责。
- 只在能澄清非显而易见的决策时才加注解。
- 行为改变时同步更新文件或情境地图。
- 保持 diff 小到可审查。
- 避免不相关的格式异动。
- 优先选择「无聊但可测试」的代码，而非炫技的写法。

使用 `ai/checklists/security-checklist.md`、`ai/checklists/testing-checklist.md`，并参照 `ai/process/review-gates.md`。

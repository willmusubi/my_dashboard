# 完成定义（Definition of Done）

任务只有在「实作」与「验证证据」两者都存在时，才算完成。

## 必要证据

- 变更的文件。
- 行为变更摘要。
- 执行过的命令。
- 测试输出摘要。
- Lint／类型检查／build 输出（如适用）。
- UI 变更的截图或视觉比对。
- UI 变更的设计系统对照：列出重用的 token 与组件；若新做了组件，
  确认已依既有 token／风格制作并登记回 `ai/context/design-system.md` 的组件库 inventory。
- 高风险变更的安全性备注。
- 已知限制。
- 后续任务。

证据写进卡片的 `evidence` 字段（`commands` / `findings` / `residual`），
不要只写在聊天里——聊天会被关掉，卡片不会。

## 不算完成

以下情况不得标记为完成：

- 测试被跳过却没有说明原因。
- 验证只是「看起来没问题」。
- UI 变更了却没有做截图审查。
- UI 用了硬写的一次性色彩／间距，而非 `design-system.md` 的 token；
  或新做的组件没有登记回组件库 inventory。
- 验收标准没有被逐条检查过。
- 实作变更了不相关的文件。
- 发现的风险没有负责人或后续处理。
- 卡片上还有人写的、未回应的决策或提问。

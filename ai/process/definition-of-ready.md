# 就绪定义（Definition of Ready）

任务只有在所有必要字段都齐备时，才算「AI-ready」。

## 必要条件

- 目标明确具体。
- 用户或系统行为清楚。
- 范围有界。
- 已列出相关文件或搜索入口。
- 验收标准可测试。
- 非目标明确列出。
- 已指定风险等级。
- 已定义验证方法。
- 已记录人工核准状态。
- 若有前置任务（`dependsOn`），前置任务须全部为 `done` 才能把这张卡标记为就绪；
  有任何一个还没完成，这张卡只能停在 `backlog` 或 `blocked`。
  （这条由看板服务端强制执行，见 `tools/kanban/server.mjs` 的 `checkDependsOn`。）

## UI 工作额外要求

- 画面名称。
- 目标视窗（viewport）假设。
- 状态：默认、加载中、空状态、错误、停用、权限不足、移动版。
- 已读过 `ai/context/design-system.md`，并列出本任务会重用的既有 token 与组件。
- 若需要的组件不在组件库 inventory 里，已标记为「需照既有风格补做并登记回 inventory」。
- 已产出 mockup 变体（皆以既有 token／组件组成）。
- **人工已选定一个变体。**
- 已列出视觉验收标准。
- 需要截图验证。

## 后端或数据工作额外要求

- API 契约。
- 数据模型变更。
- 验证规则。
- 错误处理。
- 认证与权限预期。
- 相关时的迁移与回滚备注。

## 高风险工作额外要求

高风险工作包含：认证、权限、支付、密钥、文件处理、网络访问、
数据库迁移、基础设施，以及跨服务变更。

需要：

- 架构审查。
- 安全性审查。
- 测试策略审查。
- 人工核准。

# 情境协议（Context Protocol）

情境是一种预算。要有意识地花用。

## 搜索顺序

1. 读 `ai/context/project-map.md`。
2. 读 `ai/context/architecture-map.md`。
3. 读 `ai/context/code-search-guide.md`。
4. 搜索精确的符号、路由、组件名、endpoint 路径与错误文本。
5. 读取最小范围的相关文件集合。
6. 有可用时使用语义工具。
7. 只有在证据不足时才扩大搜索范围。

## 情境包（Context Pack）

每个实作任务都应该以下列格式开始：

```text
任务：
目标：
相关文件：
既有模式：
假设：
未知事项：
允许变更的文件：
不得触碰：
验证命令：
风险等级：
```

## 搜索规则

- 文本搜索优先用 `rg`。
- 有可用时优先用具符号感知能力的工具。
- 除非任务范围是整个 repo，否则不要读整个 repository。
- 摘要或符号搜索就够用时，不要把大文件整份贴进情境。
- 摘要发现并引用文件路径。
- 发现对项目有用的知识时，更新 `ai/context/code-search-guide.md`。

## 停止条件

遇到以下情况时**停下来请示方向**，不要自己选一个继续：

- 搜索发现多种可能的实作方式、各有不同取舍。
- 需求跟既有架构冲突。
- 缺少必要文件。
- 任务涉及密钥、认证、支付、迁移或基础设施。
- 预估范围超出已核准的任务卡。

停下来的方式：在卡片上留一条提问（`comments`），并在回复里说清楚卡在哪、
有哪几个选项、你倾向哪个。不要默默挑一个做下去。
